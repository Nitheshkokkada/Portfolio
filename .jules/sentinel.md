## 2026-08-02 - Broad loadEnv and Insecure Define configuration in Vite
**Vulnerability:** In `vite.config.ts`, `loadEnv(mode, '.', '')` was configured with an empty prefix, loading all system/host environment variables during the build process. Additionally, a `define` block exposed `process.env.GEMINI_API_KEY`, which risks hardcoding secrets into the client-side JavaScript production bundle.
**Learning:** Broad environment variable loading exposed build-machine secrets to Vite. Mapping secrets to the browser via `define` performs literal string substitution at compile-time, permanently hardcoding the API key into production bundle assets, even if the key is not currently referenced in the frontend code.
**Prevention:** Avoid calling `loadEnv` with an empty prefix string; rely on standard prefixes like `VITE_` to restrict loaded variables. Remove unnecessary `define` mappings for secrets that are not used by client code, or use a secure backend API/server proxy if those secrets are required.
