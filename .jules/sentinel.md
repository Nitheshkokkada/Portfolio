## 2026-03-01 - Insecure Build-Time Secret Injection and Broad Environment Loading
**Vulnerability:** In `vite.config.ts`, a broad `loadEnv` call loaded all environment variables from the environment with an empty prefix (`''`), and a `define` block mapped `process.env.GEMINI_API_KEY` using `JSON.stringify(env.GEMINI_API_KEY)`. This created a risk of leaking arbitrary system environment variables or hardcoding the Gemini API key directly into compiled production Javascript assets during build time.
**Learning:** Vite's `define` configuration performs direct, literal string replacement on source code at build time. If an API key or other secrets are mapped in `define` and later referenced (even indirectly or via general `process.env` access), they will be bundled in plaintext into the client-side code, rendering them fully visible to any user. Additionally, calling `loadEnv(mode, '.', '')` bypasses Vite's default prefix-based loading (which defaults to `VITE_`), making all system environment variables accessible within the config.
**Prevention:** Avoid using `loadEnv` with an empty string prefix unless absolutely necessary, and never map sensitive secrets/API keys via Vite's `define` config. Use a secure backend proxy or serverless functions to interact with third-party APIs like Gemini, keeping keys secure and confidential.
