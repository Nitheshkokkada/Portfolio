## 2026-08-04 - Insecure Environment Variable Leakage via Vite Build Define Configuration
**Vulnerability:** The Vite build configuration used the `define` configuration option with `JSON.stringify(env.GEMINI_API_KEY)` and loaded all environment variables with `loadEnv`. When compiling the production assets, Vite's build-time string-replacement literally hardcoded whatever was inside the `.env` or system environment for `GEMINI_API_KEY` directly into the client-side JavaScript bundle, making the secret publicly visible.
**Learning:** Broadly loading all environment variables using `loadEnv(mode, '.', '')` can accidentally expose sensitive system-level configurations to build tasks. Using Vite's `define` with stringified secrets hardcodes the value into client-facing artifacts at compile-time, even if the runtime environment does not explicitly import it in the code source.
**Prevention:** Never use Vite's `define` option or standard client build configs to pass confidential API keys or secrets to frontend bundles. Avoid calling `loadEnv` with an empty prefix (`''`) unless strictly necessary, and enforce using secure backend proxy endpoints to access third-party services that require authorization tokens.
