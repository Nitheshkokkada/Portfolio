## 2026-03-05 - Overly Permissive Environment Variable Loading & Direct Define Injection
**Vulnerability:** Use of Vite's `loadEnv(mode, '.', '')` loaded all system-level environment variables (e.g., PATH, HOME, credentials of the build system) and allowed potentially sensitive API keys such as `GEMINI_API_KEY` to be bundled directly into production Javascript assets via Vite's static literal replacement (`define` block).
**Learning:** Broadly loading environment variables with an empty prefix (`''`) exposes non-public-safe environmental parameters. Standardizing on `VITE_` prefix prevents unintentional injection. Any backend secrets like API keys must never be mapped using Vite's static `define` replacement as they become baked into public clients.
**Prevention:** Always restrict environmental loading to specific safe prefixes (or omit `loadEnv` if not explicitly needed in config). Ensure secret tokens are proxied securely or loaded solely server-side rather than exposed to client-side bundles.
