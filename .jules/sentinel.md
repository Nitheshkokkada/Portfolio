## 2026-03-05 - Insecure Client Bundle Secret Exposure via Vite config
**Vulnerability:** The application config was loading all system environment variables using `loadEnv(mode, '.', '')` and baking `GEMINI_API_KEY` into client-side assets via Vite's `define` configuration. Since Vite compiles code for browser execution, any value in the `define` section is statically replaced and bundled into public assets, exposing private API keys or secrets to anyone visiting the site.
**Learning:** Build-time environment variable interpolation/injection using Vite's `define` or standard bundlers actually hardcodes those secrets into production JS bundles. It is an anti-pattern to pass backend credentials, API keys, or private tokens directly into the frontend build.
**Prevention:** Avoid defining client-side replacements for backend secrets. Cleanly separate client and server logic, use standard prefix constraints (like `VITE_` if environment variables are safe for public exposure), or use a backend API proxy to route sensitive requests instead of doing so directly from the frontend.
