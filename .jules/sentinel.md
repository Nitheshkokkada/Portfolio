## 2026-07-27 - Secret leakage via Vite's define configuration and loadEnv
**Vulnerability:** The `vite.config.ts` was using `loadEnv(mode, '.', '')` which broadly loaded all system environment variables, and mapping `process.env.GEMINI_API_KEY` to `env.GEMINI_API_KEY` via Vite's `define` configuration. This configuration performs direct string replacement during build time, which permanently bakes the Gemini API key into the production client-side JavaScript assets.
**Learning:** Broadly loading env variables or using Vite's `define` replacement for sensitive keys makes secrets visible to anyone inspecting the frontend bundle. Additionally, loading empty prefix environment variables can accidentally leak machine environment variables (e.g. PATH, HOME).
**Prevention:** Do not use `define` or broad `loadEnv` calls with empty prefixes to inject secrets into client-side assets. Instead, handle features requiring API keys securely via a server-side proxy or backend service.
