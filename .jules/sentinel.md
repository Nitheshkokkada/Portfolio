## 2026-03-01 - Broad loadEnv and Insecure define config in Vite
**Vulnerability:** Under `vite.config.ts`, `loadEnv` was called with a broad prefix argument (`loadEnv(mode, '.', '')`), loading all system environment variables into memory. Concurrently, a custom define block in Vite (`process.env.GEMINI_API_KEY`) was used to inject `GEMINI_API_KEY` into the frontend build. This caused build-time environment variables, including highly sensitive secrets like the Gemini API key, to be bundled directly into the client-side JavaScript bundle and exposed to all visitors.
**Learning:** Developers often confuse backend-like environment variable injection (`process.env.KEY`) with secure runtime checks. Since Vite performs static replacement during production builds for defined variables, anything passed to `define` or prefixed with `VITE_` (and used in client code) is hardcoded into the output JS assets. Broadly loading all environment variables via `loadEnv` with an empty string prefix additionally risks accidental inclusion of secret keys from the development/build server environment.
**Prevention:** Avoid using `define` to inject sensitive API keys or secrets in Vite configuration files. If an API key is required on the frontend, use the standard `VITE_` prefix and ensure no secrets are exposed. Better yet, route all API requests that require authentication through a secure backend proxy. Also, never call `loadEnv` with an empty prefix (`''`) unless absolutely necessary, to limit loaded env vars to those prefixed with `VITE_`.
