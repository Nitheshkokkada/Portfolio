## 2026-07-08 - [CRITICAL] Secret leakage via Vite build configuration
**Vulnerability:** Sensitive API keys were being injected into the client-side bundle via Vite's `define` configuration. This results in the secrets being hardcoded into the production JavaScript assets, making them accessible to any user.
**Learning:** Vite's `define` configuration performs literal string replacement at build time. Mapping `process.env` secrets here is an insecure practice for public-facing frontend applications. Additionally, using a broad `loadEnv(mode, '.', '')` call loads all system environment variables (like PATH, HOME, etc.) into the `env` object, increasing the risk of accidental exposure if that object is logged or broadly used.
**Prevention:** Never inject sensitive secrets directly into the client bundle. Use a backend proxy to handle requests requiring authentication. For non-sensitive public configuration, use the default `VITE_` prefix which only loads specifically marked variables. Always restrict `loadEnv` or remove it if not strictly necessary for the build configuration itself.
