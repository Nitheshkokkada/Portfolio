## 2026-07-19 - Secret Leakage via Vite Build-Time 'define' and Broad 'loadEnv'
**Vulnerability:** The application was configured in `vite.config.ts` to use Vite's `define` property to inject `process.env.GEMINI_API_KEY` into production assets. Vite performs literal string replacement at build-time, which bakes the secret key into client-side JavaScript assets. In addition, the config used a broad `loadEnv(mode, '.', '')` call with an empty prefix, loading all system/host environment variables into memory, which risked exposing highly sensitive machine-level environment variables (e.g. system PATH, HOME) during the build.
**Learning:** Build-time environment variable replacements like Vite's `define` are highly insecure for backend-only secrets or API keys because any value mapped is compiled directly into the client-facing static distribution. Furthermore, when loading environment variables via `loadEnv`, using an empty prefix pulls in system-level environment variables, which can lead to accidental exposure of server/CI secrets or information disclosure.
**Prevention:** Avoid injecting secrets directly into client-side bundles. Any API interactions requiring private keys must be proxied through a secure backend server. When environment variables are needed, only load those with specific secure prefixes (like `VITE_`), and avoid empty prefix options in `loadEnv` calls unless absolutely necessary and secure. If an API key or secret is no longer referenced in the source files, proactively purge its build mappings and load configurations.
