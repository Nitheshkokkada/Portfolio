## 2026-07-30 - Exposure of build-time secrets and broad loadEnv in Vite configuration
**Vulnerability:** The Vite configuration used `loadEnv(mode, '.', '')` which loaded all environment variables from the system (including sensitive ones like PATH, HOME, etc.) and explicitly defined `process.env.GEMINI_API_KEY` via Vite's `define` mechanism. In client-side single page applications (SPAs), `define` performs static text replacement during bundling. This means any environment variables defined this way are permanently baked into the public client bundle, leading to critical secret exposure.
**Learning:** This existed because the template originally used the Gemini AI package on the frontend, but the client code was updated without cleaning up the build configuration. Dead or unused configuration code can continue to leak build-time secrets or unnecessarily expose the build system's environment variables.
**Prevention:** Always remove unused dependencies and their associated configuration blocks. Avoid using broad `loadEnv(mode, '.', '')` filters unless strictly required, and rely on Vite's default prefix `VITE_` to load environment variables securely. Do not inject sensitive secrets into the frontend bundle via `define`.
