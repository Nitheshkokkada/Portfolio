## 2026-03-08 - Broad Environment Loading and Insecure Secret Bundling via Vite Configuration
**Vulnerability:** The Vite configuration used `loadEnv(mode, '.', '')` with an empty prefix which loaded all system environment variables (including sensitive keys like PATH, HOME, and other server-side/CI secrets) into memory. Furthermore, it defined `process.env.GEMINI_API_KEY` mapping to Vite's literal string replacement mechanism (`define`), which compiles and hardcodes environment-specific secrets directly into the production JavaScript client-side bundle.
**Learning:** Broad environment variable loading combined with the `define` replacement mechanism in frontend build tools often causes severe, accidental leakage of sensitive backend credentials, system environments, and third-party API keys within client-side production assets.
**Prevention:** Restrict loaded environment variables to specific safe prefixes (like `VITE_` by default), avoid loading all environment variables with empty prefixes, and always refrain from hardcoding or bundling API keys and secrets directly into the client bundle; instead, use secure server-side proxies or runtime-loaded dynamic configuration for sensitive API integrations.
